## Findings

1. **[P2] Failed canonical execution can be reported as a new success.** [executors.ts](../../app/worker/executors.ts), lines 3 and 13–15, awaits a `Promise<void>` callback then takes the last retained legacy run. [main.ts](../../app/main.ts), lines 1514–1525 and 1663–1667, returns normally on invalid input/budget refusals and catches worker failure. With an earlier run retained, entering `d` in the world and invoking the shared canonical producer can therefore return the old run and display “receipt validated and admitted” ([shared-inspector.ts](../../app/views/shared-inspector.ts), lines 98–101). Return the exact new receipt or explicit refusal; store ordering cannot identify this execution. Retained live evidence covers successful requests, not this failure path.

2. **[P2] Direct legacy import omits the archived snapshot-ID invariant.** [legacy-run.ts](../../archive/legacy-run.ts), lines 10–12, checks `hash(snapshot.state) == startingSnapshotId` and `startingCheckpointId == snapshot.id`, but not `snapshot.id == hash(snapshot.state)`. [integrations.ts](../../trace/integrations.ts), lines 11–12, calls it directly, bypassing [SessionArchive.addSnapshot](../../archive/session.ts), lines 42–44. In an otherwise valid saved envelope, changing only `snapshot.id` and `startingCheckpointId` to the same arbitrary string passes the inspected checks and presents that string as the checkpoint identity. Restore the complete archived-snapshot identity check at the codec boundary. The retained canonical recording has matching IDs; it does not exercise this malformed import. This concerns identity validation, not a claim that hashes authenticate measurements.

3. **[P2] Replacing the canonical player retains an invalid offset and replay label.** [shared-inspector.ts](../../app/views/shared-inspector.ts), line 27, installs a fresh player while closed without resetting `#offset` or `#replay`. Select canonical `mlpUp`, set offset 31, close, Predict and reopen: the new first point has eight values, so line 66 requests count `-23`, which [EvidenceStore.slice](../../trace/evidence.ts), lines 109–111, rejects. The [retained canonical recording](../../test-results/m0-m1-first-slice/canonical-saved.json) confirms `mlpUp` length 32 and first `tokenEmbedding` length 8. A prior saved selection can also leave fresh evidence labeled SAVED REPLAY. Change run, point, coordinate and replay state together, resetting or validating each. The recorded browser routes do not cover this transition.

These are static control-flow/data findings, not executed reproductions. Each needs a focused regression in a separately authorized repair task; no arithmetic, fixture, tolerance or model-capability change is indicated.
