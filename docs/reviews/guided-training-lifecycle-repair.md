## Causes established on current source

The original focused reproduction
[report](../../test-results/scratch/browser-0PvbpW/report/results.json) and
[source receipt](../../test-results/scratch/browser-0PvbpW/source.json) retain four
failures: desktop ten-count assertions saw eight after five seconds; the held tenth
admission predicate never reached its boundary within five seconds; the delayed
third-result test restored two. A preceding sandbox attempt could not bind the local
server (`EPERM`) and remains in `browser-sGgwZi`; it proves no browser behavior.

The instrumented starting-source
[report](../../test-results/scratch/browser-Y3ukrL/report/results.json) separates the
causes. A real ten-update batch reached terminal completion in about 7.2 seconds,
with actual tenth result and exact endpoint. No capacity alert or early stop occurred.
`SessionRetention.begin()` measures the current portable footprint and forks its
archive before transport. The old fork replayed every retained snapshot/run/experiment
through validators and codecs on every update. Profiling shows growing main-thread
archive validation, rather than ten expensive native mathematical updates, dominates.

The original cancellation injection withheld the third Worker message **before**
calling the client handler. The client therefore had no matching acknowledgement;
reset terminated that worker, restored step two, and correctly rejected the released
old-generation reply. Its archive delay intercepted snapshot hashing during restoration,
not acceptance of the third result. The repaired test preserves the held-reply control
and asserts step two, its exact probability/source, and a distinct withheld run.

A separate deterministic injection calls the authentic client handler and immediately
clicks Cancel in the same task, before the resolved Promise's `execute()` continuation.
On starting source, worker restoration reached step three while the displayed count
and comparison stayed at two. `reset()` captured only `lastAcceptedResult`, updated
by the later application continuation, although the client had synchronously recorded
a newer completed snapshot. This is an acknowledged-state publication defect.

## Repair and state preservation

- `SessionArchive.fork()` and `EvidenceStore.fork()` copy isolated private map
  membership over records already validated and deeply frozen on admission. Payload
  bytes use the existing transaction-local layer. Existing content IDs, original
  envelopes, codec metadata, variant/data receipts and portable ordering survive
  exactly. New admissions and every portable import still run their strict validators;
  no public unvalidated map insertion API was added.
- The client exposes its synchronous matching acknowledged result. Cancellation
  captures it before resetting the epoch, checks the restored complete snapshot ID,
  and publishes count, source, step and numerical comparison before fallible archive
  work. Repeated teaching uses the new batch's actual baseline distribution.
- Cancellation hands off the original pre-execution retention reservation rather
  than cancelling it and appending accepted evidence directly to the global archive.
  Superseded `execute()` continuations cannot cancel the handed-off reservation.
  Reset/Clear still invalidate reservations and old responses. Execution checks its
  operation again after asynchronous reservation and before worker transport.
- Persistent admission failure preserves accepted result/history in memory, exposes
  retention failure, and refuses another canonical execution while its learning
  receipt is unretained. Clear Session remains an explicit user action. Failure is
  never presented as discard or rollback. Cancellation admission failure likewise
  leaves the acknowledged count, source and complete restored state visible.
- A new Teach request that refuses before any acceptance retains the preceding
  numerical comparison. Genuine capacity refusal terminates a partial lesson without
  transporting its next update. Hard limits and reservation bounds are unchanged.

No production arithmetic, oracle, fixtures, tolerance, schedule, parameter order,
recording format, archive identity algorithm, or replay reader was changed.
